# Vibe Coding Prompt Pack

These prompts assume you are working inside the Maestro template with Claude Code or Codex. Replace brackets with your facts.

## Orient

1. “Read the repository instructions and explain the supported way to add [feature]. Name the canonical owner, files likely affected, and gates before editing.”
2. “Map the existing route, screen, feature, backend contract, and storage path for [capability]. Do not invent a second system.”
3. “Show me the smallest useful product slice for [buyer outcome]. Separate must-have behavior from later polish.”

## Plan

4. “Write a plan for [feature] with user-visible acceptance criteria, failure states, privacy assumptions, and focused verification.”
5. “List the decisions only I can make in plain language. Make safe technical choices yourself.”
6. “Find reusable shell, block, form, and data primitives before proposing new components.”

## Build

7. “Implement the approved slice. Preserve tenant ownership and fake-safe local behavior. Stop if the product requirement changes materially.”
8. “Create loading, empty, error, list, detail, and success states for [workflow].”
9. “Make the desktop and mobile composition intentional. Keep primary actions unmistakable.”
10. “Add the typed backend contract first, then connect the UI to that real path.”

## Debug

11. “Reproduce [bug], identify the first incorrect state transition, and show evidence before changing code.”
12. “Trace this from browser action through route, contract, backend function, and stored record.”
13. “Compare expected and actual behavior. Give me the smallest fix that preserves existing ownership.”

## Prove

14. “Run the focused tests for the changed system, then the required handoff gates. Report exact failures without hiding them.”
15. “Verify the built app, not only source code. Check the real route, visible states, network errors, and mobile layout.”
16. “Create a delivery receipt: commit, commands, checks, known limitations, launch URL, and rollback target.”

## Improve

17. “Audit this screen for hierarchy, readability, action clarity, empty space, touch targets, and generic AI-looking patterns.”
18. “Find duplicated concepts or systems introduced by this change and converge on the canonical owner.”
19. “Explain this feature to a nontechnical owner in five sentences, including what remains fake or unconnected.”
20. “Turn the repeated work in this session into a small reusable skill with triggers, steps, and verification.”
